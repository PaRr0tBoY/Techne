---
description: "收尾开发工作：暂存相关文件、commit、push、创建 PR、清理开发环境"
---
将当前开发工作收尾并完成交付。

执行流程：

检查当前工作区的所有变更，仅暂存与当前分支开发主题直接相关的文件，不得将无关修改、临时文件、调试代码、格式化噪声或其他功能改动一并提交。
创建一次 Git Commit。
Commit Message 使用英文。
优先遵循项目已有 Commit 规范（如 Conventional Commits）。
若项目无规范，则使用清晰、简洁、描述性的英文 Commit Message。
Commit Message 应准确说明改了什么，而不是做了什么。
推送当前分支到远程仓库（若尚未推送）。
创建 Pull Request，将当前分支合并至 main。
PR 标题应准确概括本次修改。
PR 描述应包含：
修改内容摘要
修改原因
主要实现方式
验证方式
是否存在已知限制（如有）
若项目已有 PR 模板，则遵循模板填写。
PR 创建成功后，清理开发环境。
删除本地开发分支（仅当其已成功合并或用户明确允许删除时）。
删除对应的 Git worktree（若存在）。
清理失效的 worktree 引用。
不删除 main、默认分支或其他无关分支。

要求：

不提交无关文件。
不执行 git add . 或其他会无差别暂存全部文件的操作，除非已确认所有修改均属于本次开发内容。
提交前检查工作区，确保不存在误提交。
PR 的目标分支固定为 main。
若已有针对当前分支的 PR，则直接复用，不重复创建。
若任一步骤失败，应停止后续流程，并保留现场，不进行分支或 worktree 清理。
整个流程不得执行强制推送（--force、--force-with-lease）或任何可能造成数据丢失的 Git 操作。

完成后返回：

Commit Hash
Commit Message
Pull Request 链接
PR 编号
清理内容（删除的分支、worktree）
剩余未提交修改（如有）
执行过程中发现的异常或需要用户关注的事项。
